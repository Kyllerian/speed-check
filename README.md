# Speedcheck

Скрипт для оценки скорости скачивания с указанного HTTP(S)-адреса. Он последовательно выполняет заданное пользователем количество запросов, каждый раз полностью читает тело ответа и показывает прогресс. После завершения выводятся среднее время запроса, общий объём данных и средняя скорость.

### requirements:
    - python 3.9+
    - урл тестового файла ('https://mmatechnical.com/Download/Download-Test-File/(MMA)-1GB.zip')


Количество запросов передаётся параметром `-n` или `--count`.
По умолчанию выполняется 10 последовательных запросов.

Параметр `--timeout` защищает скрипт от бесконечного ожидания, если сервер перестал отвечать или сетевое соединение зависло. По умолчанию тайм-аут составляет 30 секунд. При работе с медленным или нестабильным сервером его можно увеличить

### Запуск с 6 запросами:
```bash
python3 speedcheck.py --count 6 --timeout 60 'https://mmatechnical.com/Download/Download-Test-File/(MMA)-1GB.zip'
```
Без тайм-аута выполнение может зависнуть при установлении TCP или TLS-соединения, ожидании HTTP-заголовков или очередной порции данных, а также после обрыва соединения, которое операционная система всё ещё считает открытым.

В результате скрипт не перейдёт к следующему запросу, не рассчитает итоговую скорость и может оставаться запущенным неопределённо долго. Само отсутствие тайм-аута не создаёт сетевую ошибку — оно не позволяет программе вовремя обнаружить такое зависание и корректно завершиться с сообщением об ошибке.

### Как считается результат

- Время одного запроса измеряется монотонным таймером от начала открытия URL до полного чтения тела ответа. В него входят сетевые задержки, установка соединения и скачивание.
- Объём определяется по фактически прочитанным байтам, а не по заголовку Content-Length.
- Мегабайт считается в десятичной системе: 1 МБ = 1 000 000 байт (степени двойки для размера файлов в ОС не используются).
- Итоговая скорость вычисляется как (все скачанные байты)/(суммарное время). Это корректнее, чем усреднять скорости отдельных запросов - медленные и быстрые запросы получают вес, соответствующий их длительности.
- Результат выводится в Мбит/с (1 байт = 8 бит).

Запросы намеренно выполняются последовательно. Если любой из них завершается сетевой ошибкой, HTTP-ошибкой или тайм-аутом, скрипт прекращает работу и возвращает ненулевой код выхода, чтобы не выдавать неполный замер за успешный.

Во время скачивания строка текущего запроса обновляется на месте и показывает номер запроса, процент и объём данных.
Если сервер не прислал Content-Length, процент определить нельзя, поэтому отображается только уже скачанный объём.
Работу можно остановить сочетанием Ctrl+C (в этом случае скрипт завершается с кодом 130).

Скачанное содержимое не сохраняется в файлы: оно читается небольшими блоками только для подсчёта байтов и сразу отбрасывается.
Поэтому после успешного завершения, сетевой ошибки или остановки пользователем на диске не остаются тестовые файлы. Это также не позволяет скорости записи накопителя и свободному месту влиять на сетевой замер.

### Ограничения

Это прикладной замер скорости до конкретного сервера, а не универсальная оценка тарифа провайдера. На результат влияют расположение и нагрузка сервера, маршрутизация, CDN/прокси, Wi-Fi, фоновые загрузки, DNS/TCP/TLS и производительность самого сервера.
Скрипт отправляет Accept-Encoding: identity, чтобы сервер по возможности не применял сжатие и счётчик отражал фактический объём переданного тела ответа.

### Тесты

Тесты поднимают локальный HTTP-сервер, поэтому не зависят от внешнего интернета:

```bash
python3 -m unittest discover -s tests -v
```
